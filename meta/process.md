# Meta — Process & Methodology Notes

## Our Working Method

Every behavior is approached as a **scientific experiment**:

```
1. Grounding   → understand the architecture + why refusals happen
2. Mapping     → exhaustively map the attack surface
3. Hypothesize → generate a strategy tree (vectors + expected resistance)
4. Execute     → run attempts as hypothesis tests, not random tries
5. Debrief     → treat outcomes as evidence about model behaviour
6. Document    → publish the science, not the exploits
```

## Collaboration Model

- **Student:** crafts prompts, executes in lab, reports outcomes
- **Claude (thinking partner):** provides architecture grounding, pushes
  scientific framing, helps interpret refusals as diagnostic signals,
  challenges lazy thinking

## What Gets Published Here

✅ Architecture analysis
✅ Attack surface maps
✅ Strategy trees (vector categories, not raw prompts)
✅ Outcome analysis (what refusals reveal)
✅ Lessons that generalise
